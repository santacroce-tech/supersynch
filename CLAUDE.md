# CLAUDE.md — SuperSynch

Native iOS/iPadOS 17+ remote controller for Syncthing, built on its REST API. It does not run Syncthing.

## Build / test
- The project is generated by XcodeGen from `project.yml`. **Never hand-edit or commit `SuperSynch.xcodeproj`** (it's gitignored). Run `xcodegen generate` after adding or removing files.
- `scripts/test.sh [device]` regenerates the project and runs all tests (default device: "iPhone 15", on iOS 26.5).
- Raw command: `xcodebuild -scheme SuperSynch -destination 'platform=iOS Simulator,name=iPhone 15' -derivedDataPath build/DerivedData test`
- Live integration tests: set `TEST_RUNNER_SYNCTHING_URL` and `TEST_RUNNER_SYNCTHING_API_KEY` (see README).
- UI checks without a server: launch with `-DemoMode` (optionally `-DemoSection folders|devices|dashboard|pending -DemoFolder <id>`), then take screenshots with `xcrun simctl io <device> screenshot`.
- The build must stay warning-free under Swift 6 with `SWIFT_STRICT_CONCURRENCY=complete`.

## Architecture
```
SyncthingKit/ (framework, idiom-agnostic — the ~98% shared core)
  Models/        Codable REST models. Lenient decoding via KeyedDecodingContainer.lenient*
  Networking/    SyncthingAPIClient protocol, SyncthingHTTPClient (URLSession),
                 TrustEvaluator (cert pinning), SyncthingError (human messages)
  Persistence/   ServerStore (UserDefaults JSON), SecretStore/KeychainSecretStore
  Live/          ServerState (value snapshot), EventReducer (pure), ServerSession
  ViewModels/    AppModel (servers + sessions + scene phase), ServerEditorModel
  Support/       Decoding helpers, JSONValue, MockSyncthingAPIClient + MockData
SuperSynch/ (app, SwiftUI views only)
  Views/Adaptive/ RootView picks PhoneRootView (NavigationStack) or PadRootView
                  (NavigationSplitView) by horizontalSizeClass. ONLY idiom-specific code.
  Views/*         Shared screens. Lists take an optional `selection` binding
                  (SelectableList) so the same view serves the stack and the split view.
SyncthingKitTests/ fixtures (from the docs) + decoding, reducer, client (URLProtocol stub),
                   session/store/editor tests, opt-in LiveIntegrationTests
```

### Data flow
1. `AppModel` owns `ServerStore` and one `ServerSession` per server. Only the selected session runs, and only while the scene is `.active` (`setActive`).
2. `ServerSession.start()` runs two tasks:
   - **Event loop**: `events(since:0, limit:1)` to get a cursor, then `fullRefresh()`, then long-poll `events(since: lastEventID, timeout: 60)`. Batches go through `EventReducer.apply(_:to:)`, which returns `EventEffect`s that the session then executes (refresh config, pending, folder status, device completion, or a full resync). Transient errors trigger a backoff and a resync; non-transient ones (401, cert) set `.failed` and stop.
   - **Poll loop** (every 10 s): connections (for rates) and status (detects restarts via `startTime`). Every 3rd tick it also polls errors and stats. While the event stream is down, it additionally polls config, folder statuses and pending requests.
3. Views read `session.state` (`ServerState`, `@Observable` through the session) and call session actions. Failed actions set `session.actionError`, which is shown as an alert.

## Conventions
- **Verify endpoint shapes against the docs** (https://docs.syncthing.net/dev/rest.html; raw sources in github.com/syncthing/docs `rest/*.rst`, `events/*.rst`). Config JSON tags come from `lib/config/*.go` in syncthing. Don't invent shapes.
- Every model gets a hand-written `init(from:)` built on the `lenient*` helpers. Missing, null or mistyped fields must fall back to defaults and never throw. Timestamps use `SyncthingDate.parse` (nanosecond RFC 3339; Go zero time → nil).
- When writing config back, use `PATCH` for single fields. To build new objects, start from `/rest/config/defaults/*` as `JSONValue` so unknown fields are preserved (see `PendingActions`).
- Keep live-update logic in `EventReducer` / `ServerState` (pure, testable). Put side effects in `ServerSession`.
- Add fixtures for new endpoints under `SyncthingKitTests/Fixtures` and a decoding test for each.
- Never log API keys. Secrets go only through `SecretStore`. No analytics.
- Never disable TLS validation. Self-signed certs are accepted only through a per-server SHA-256 pin (`TrustEvaluator`).
- User-facing strings: SwiftUI literals in the app. In the framework, use `String(localized:bundle: SyncthingKit.bundle)`. Localizable.xcstrings holds the English baseline.
- Colours: semantic system colours only (Dark Mode). Animations must respect `accessibilityReduceMotion`.
- Commits: small, logical, with assumptions noted in the message.
